The attention pilot completed saving defaults, in-page proposal save/reopen at
revision 2, filtering, keyboard selection, discard, and local unsaved-navigation
guards. It also reported that sidebar Usage navigation discarded an unsaved
choice. **This is a fixture observation, not an established production defect.**
That existing fixture mounts `OperatorShell` without the application's navigation
handler; sidebar navigation reloads the fixture. The application root instead
owns route transitions. The destination was explicitly outside pilot scope, so
this finding needs a targeted app-root check before any product correction.
It demonstrates why coordinator triage must retain environment boundaries.

All three deliberately introduced symptoms were found in one pass each. This is
three selected examples, not a detection-rate estimate. No in-scope defect was
reported for the clean repertoire control. The additional attention observation
was retained with its fixture limitation rather than counted as a production
bug or silently discarded. Linguistic quality, persistence for the simulated
runs, provider results, hosted authentication, and deployment were not evaluated.

historical memory context in addition to the assignment. They did not receive
the implementation conversation or seeded defect inventory. This was fresh task
context with a browser-only role, **not enforced tool/filesystem isolation**.

The host does not permit subagents to request browser visibility. Several agents
first requested it, then recovered with a background tab. Some tool replies
required reacquiring an existing tab. These were environment issues, not source
investigation. The procedure's invocation guidance should avoid explicitly
requesting visibility for a subagent in this host.

An earlier attention attempt (`01a1b233-d596-7813-8d60-a1a0f8890ab9`)
was interrupted by a coordinator fixture edit/HMR reset and then a usage limit.
It was excluded from completed results and replaced by a fresh agent. Later
passes ran against frozen served files, and first-pass findings were complete
before the defect inventory was revealed. The freeze requirement is part of
coordinator guidance because of this observed failure mode.

## Separate implementation verification

The coordinator also exercised the real-backend `persist` fixture through the
normal operator UI: edited the proposal, saved, reloaded and saw the edited cue,
and applied it. A read-only SQLite inspection then found proposal status
`applied`, proposal version 2, and source version 2 containing the edited cue.
This is real local HTTP/SQLite/approval-worker evidence; it is not a blind-agent
persistence trial.

Focused fixture/attention/repertoire checks passed. The full Node suite passed
with 2,544 passes, zero failures, one skip and one todo (2,546 tests); production
TypeScript/Vite build passed. An initial sandboxed full-suite attempt failed on
listener-dependent tests and stalled; it was stopped and rerun with local
listener access. Generated databases and routine run artifacts were kept outside
source control. The planted faults were removed from the working implementation
by returning to the clean stack, while their separate local branch and patch
were retained.
