# Mandarin Journal prototype

A local, single-learner app for trying a reading, a casual Mandarin conversation, and short practice with one continuous tutor. It has its own package, server, and SQLite journal. Readings, actions, and study records stay separate from the hosted study app.

The journal is planned to replace the hosted app. [The journal's learning model](MODEL.md) explains that direction and the principles behind practice, priority, teaching and the record; read it before changing them. [The journal's interface](DESIGN.md) records the design direction, current observations and open questions for what the learner sees.

## Run

Use Node 24.13 or newer. From this directory run:

```sh
npm ci
npm start
```

Open the address printed at startup (**http://127.0.0.1:4320** for the default fixture). With no API key the footer says **Demo tutor** and the server uses short scripted examples. The scripted tutor has examples for birdwatching, 只 and 只是, 透透气, and getting distracted at the library.

To use the real agent, supply `OPENAI_API_KEY` in the environment or in an ignored `.env`. `npm run start:live` and `npm run start:copy` read the repository root `.env` and then this directory's `.env`, with values here winning. Plain `npm start` reads only this directory's `.env`, so the default fixture stays on the offline tutor in every worktree. The tutor and conversation partner default to `gpt-6.2-sol`; set `JOURNAL_MODEL` to change it. Teaching a new word uses `gpt-6-luna` with high reasoning effort, as the hosted app's introductions did; set `JOURNAL_TEACH_MODEL` to change that alone. The footer says **Live tutor** when provider mode is configured. A learner action can send its text, source passage or exercise, and relevant journal history to the model. `JOURNAL_DEMO=1` forces offline mode.

Which journal opens is separate from the tutor mode. `npm start` opens this checkout's fixture, a realistic demo week built on first start. `npm run start:live` opens the real journal, which lives outside every checkout and only opens from the primary checkout. `npm run start:copy` opens a copy of it made with `npm run journal:copy-live`. The [runbook](RUNBOOK.md) covers paths, ports, updates, backups and restore.

## Home

Home is a cork wall with four entrances. Practice is a ticket, Read a dog-eared page, Talk a postcard, and Scrapbook a shoebox. The ticket opens the current session, the page resumes an unfinished reading at the quoted paragraph, and the postcard opens the named conversation. **Just talk** starts a casual conversation. Select the piece on the shoebox label to find it on the table. When no reading has a bookmark in progress, **Bring a reading** opens reading import. The notepad on the wall accepts a word, a link, or a sentence. The [delivery slices](design/delivery.md) record the release scope.

Open the shoebox for the scrapbook table. Each conversation and reading has its own cluster of pieces. A check by a reading means its bookmark is on the last paragraph. Reopen it and scroll to an earlier paragraph to put it back in progress. A one-paragraph piece gets its bookmark when you leave it. Words without a source collect under Loose ends. Drag or scroll to move around the desktop table, pinch or Ctrl/⌘-scroll to zoom, or choose **See everything** from its menu. The phone lays out the clusters vertically.

Use the **•••** button on a reading or conversation to archive it with its pieces, or delete its entry from the scrapbook. The scrapbook menu’s **Archive** opens the list of items you can restore. Each piece also has a delete action, including pieces under Loose ends. Deleting a margin note also removes it from the source margin. An attached clipping leaves the board when you delete the piece it belongs to. Learning history and practice targets are preserved.

After a word is saved or a note is made on a reading, the journal may find a credited Wikimedia Commons picture for it. A strong case is placed as a clipping beside its piece; a weaker one waits on the piece and shows a small **picture ↗** cue when you hover or focus it, with **Keep on board** and **Not for me**. **Pictures: off / quiet / normal** in the menu controls how much shows. [Media on the board](MEDIA.md) describes the judgment model and the composition policy.

## Try a learner journey

Talk, Tutor and margin questions show your submitted words immediately and leave room to draft a follow-up. Live Talk fills in the partner’s reply as it arrives. Tutor exchanges appear when the journal has checked the reply and saved any requested action. You can close a margin question and reopen its marker while the tutor works. If a reply is interrupted, **Retry** recovers the same turn and keeps your next draft.

1. Open **Talk** and start a thread about birdwatching. Describe putting out seeds or waiting to see the birds. Reflect on the exchange, follow a quoted takeaway to the original message, and ask the tutor about it. Opening the same reflection again retrieves the saved review. More messages in this thread start a new stretch.
2. Ask the tutor for later practice with 只 and 只是. You can ask whether it is queued or look in the activity view in Saved. Open Practice and answer. Full feedback stays with your attempt. A tutor observation can link back to it later, and you can start a direct discussion from the feedback.
3. Open **河边的报刊亭** from the scrapbook table and tap 刊 in the opening paragraph. The reader underlines 报刊亭 and shows its pronunciation and meaning there. Tap 刊 in the gloss to inspect the character. Use the floating **← Home** link to return to the wall. Open the shoebox and choose **散场以后** from the table and try 听着听着 for an example of repeated action. Tap any Han character in a built-in or imported passage for a lookup. A clean local match can return immediately. Ambiguous catalog entries use a fast sense selector, and unresolved lookups can ask the contextual model. Six authored examples also work offline. Use **Check in context** for a second look at a quick answer and **Mark as wrong** to flag a contextual answer. Keyboard users can Tab to a lookup and press Enter. Selecting text offers **Look up**, **Save**, and **Ask** for the exact quote, including across paragraphs. **Save** keeps the occurrence in the journal. Choose **Save with note** to attach a thought such as “practice the way these two clauses fit together.” The note and its passage are available to the tutor when generating later practice. Saved passages share one bookmark in each paragraph. Reopen it to read or add a note. **Ask** opens a margin conversation where you can ask the tutor or leave a note. The progress line beneath **Home** follows the text as you scroll. Reopening the story resumes at your paragraph.
4. Bring a public article onto the table with **Import reading** in the scrapbook menu, or drop a URL into the wall’s notepad. The importer checks the extracted text for verification, sign-in and error notices before saving it. For ambiguous pages in live mode, one text-only decision call receives a bounded excerpt. Set `JOURNAL_IMPORT_MODEL` to override its default, `gpt-5.4-mini`. When the judge flags the text or cannot decide, the reader previews the result for confirmation. If a source asks for verification, choose **Paste article text** to import a copy with its original URL. The offline demo uses the same preview without making a model call. You can mark it, resume it and discuss it like a built-in reading. When you choose **Discuss in Chinese**, you open the conversation and decide how it begins.
   To bring in a PDF, choose **Upload PDF** in the Home import panel. The browser extracts selectable text and saves it as a reading. The file itself stays in your browser. Image-only scans need OCR first. The prototype accepts files up to 20 MiB and 300 pages, with up to 120,000 characters across 2,000 extracted paragraphs.
5. Use **Send** on the wall’s notepad to bring something to the Journal. Try 值得 on its own: the tutor explains it, and adds one line saying it will come into practice only if the journal admits it. Try 图书馆, which the offline demo leaves as a piece without practice, and **save 图书馆**, which always admits it. Then try asking what 值得 means in a sentence. A standalone web address opens the reading importer with the address filled in. If the Journal needs to know what you want to do with a passage, or which sense of a word you meant, continue the exchange in **Tutor**.
6. Practice runs as a session of about ten minutes. Enter checks typed recall, Ctrl/⌘+Enter sends an open reply, and Space advances through teaching and continues after feedback. The first card arrives with one model call; the next two are prepared in the background while you answer, so moving on rarely waits. A new word is taught on a lesson card you step through and then leave; it comes back as a typed recall after two other cards. The ten minutes are a rough box: when they are spent the session ends, unless a word taught in it still waits for its recall, which then comes next. **Keep going** adds five minutes. Any answered exercise can be flagged as bad, and then counts for nothing. After two failed preparations in a row the session pauses; **Try again** resumes it with the same time. The session keeps the latest failure reasons with their times in `practice.session.errors`, and the server console logs each one. A practice deck saved before sessions existed is put away when the journal opens, and its unattempted personal cards return to the queue. A session from the removed Build vocabulary mode, which taught a word on the exercise card itself, is put away the same way, but its cards are dropped rather than queued. With learner material available, Daily mix requests contextual exercises, remembering recent prompts. A fresh journal has a small starter catalogue. To watch background preparation offline, set `JOURNAL_DEMO_DELAY_MS=3000` so each offline tutor turn takes about as long as a live one. When there are misses to revisit, **Start a session with missed exercises** replays choice and recall cards whose latest attempt was an unflagged miss. **Start regular practice** returns to the usual session. Going Home during either session lets you resume it from the ticket. An open card is a line someone says to you, and you reply as yourself; its feedback has no grade.

The [reader runbook](RUNBOOK.md#lookup-dogfood-and-decision-ledger) covers model configuration, exporting dogfood decisions, and inspecting the growing dictionary with `npm run journal:dictionary`. The [lookup comparison](lookup-experiment/README.md) replays 24 taps and selections with a local dictionary, Gemini Flash Lite and Sol.

## Implementation

One tutor runs via the TypeScript Agents SDK in five situations: a direct exchange, word intake, reflection, exercise feedback and practice generation. These situations in `situations/` share the tutor's voice and evidence rules and each adds its own instructions, input, output schema and validator. Home handles standalone web links directly. For other submissions, a separate capture decision selects word preparation, a direct tutor exchange, or a clarification question. Its live classifier receives the submitted text and context. The offline fixture uses scripted decisions. Two back-office situations never speak to the learner: `admit` decides whether a word the learner asked about is also taught ([Intake and admission](#intake-and-admission)), and `mediaConsider`, which a background job asks, after a word is saved or a reading note is created, whether a Wikimedia Commons picture could join that piece ([Media on the board](MEDIA.md)). The offline demo uses canned pictures for 报刊亭 and 鸟食 and makes no network requests. The journal validates every live or offline result before applying it. The server supplies relevant activity, recent turns and recorded practice status. The tutor can retrieve earlier records and link a direct exchange to a reading passage, reflection or particular exercise attempt. A separate conversation partner has the topic and the history of its selected thread. Reflection freezes the new stretch and anchors its takeaways to exact learner quotations. On both reading and chat surfaces, margin threads store the selected range and its conversation. Existing reading notes and reflection takeaways reopen as threads. Saved provides an index back to the original context. Direct requests can save a word or note or queue a completed exercise. Exercise feedback can yield a short observation for the global stream.

Open **Model activity** from the scrapbook menu to inspect model calls, estimated or reported spend, tools, and the actions and background jobs that caused them. The [operator runbook](RUNBOOK.md#inspect-model-activity) explains how to read the ledger. The live server uses the project associated with its API key. To inspect activity in OpenAI Platform, open that project's Analytics, then Usage for requests and tokens or Spend for costs. Using a separate key for the prototype makes its calls distinguishable from the hosted app. The offline demo makes no model requests.

Local SQLite stores a single learner’s journal and idempotency receipts. Thread histories, reflections, annotations, queued cards, attempts, tutor observations and action history persist across restarts. Existing prototype journals acquire a first thread and keep their earlier messages and practice records. A request is serialized and its effects commit together. Talk sends text updates over the action response, followed by the committed state. Partial replies stay in the browser. A retry uses the original action ID and can recover the completed exchange even if the connection closed before its final update arrived.

The first personalized round can start with one exercise or previously queued cards. Continuing can generate up to three more at a time. Open responses receive feedback without a correctness grade. The journal has no mastery transitions or timed SRS scheduler.

### The record and priority

Beside the journal state, the same SQLite file keeps a record (`record.ts`): **events** for what the learner did, in their own words (chat lines, questions to the tutor, notes, saved passages, added words, exercise answers); **judgments** that interpret events; and **targets**, the words, expressions and constructions being trained. Events commit with the action that produced them. The first open with this version converts earlier activity into events without times.

A background job reads learner language the tutor has already responded to, once (`situations/notice.ts`, never shown to the learner): each question, note and open answer, and chat through its reflection, with the takeaways the learner read. For a reflection it records flaws and needs only where the takeaways addressed them, so practice follows what the learner was shown. It records expressions used naturally or with a flaw, needs where the learner reached for something they lacked, and, for an exercise, whether each intended expression was used or avoided. It receives what the tutor already said about the text and stays consistent with it. Choice and typed recall answers are judged by rule. Converted history is never sent to the model. Each judgment names its source, so judgments can be rerun; only the newest reading of an event counts.

`priority.ts` (version 0) ranks targets from the record. A need, flaw or miss raises a target, fading by half every two weeks; two clean days after the latest weakness retire it. A word taught on a lesson card follows its own lifecycle instead (below). A clean day needs a correct typed recall, or natural use in the learner's own language outside practice. A correct choice is recorded as recognition and counts for nothing; a wrong one is a miss. Use of an expression in an open answer never counts as clean, because the card steered toward it, and an open answer that does without an expression is no weakness; a flawed use there still raises the target. Saved words that were admitted ([below](#intake-and-admission)) and not yet practiced rank next. Words brought in from the hosted app contribute at most 0.3 (a fresh need scores 3), ordered by due date, miss rate and recency of the last miss. Unstudied words from the hosted stash wait to be taught like journal saves; unstudied bulk-repertoire words are not imported. Practice already done today waits. An exercise the learner flagged as bad (a `flag` event naming its answer) counts for nothing. New words have backpressure, as in the hosted app: at most five are taught a day, none while eight weaknesses or settling words are open, at most one in any four cards of a session, and none with less than three minutes left in the session's box.

A new word is taught on a lesson card: ordered beats the learner advances with Space or Continue, and nothing to answer (`situations/teach.ts`, adapted from the hosted [teaching](../../server/word-content/prompts/teaching.md) and [bootstrap](../../server/word-content/prompts/bootstrap.md) prompts). The lesson opens with a scene, and the validator rejects one that opens with a note. When the learner met the word somewhere, the passage around it or what they wrote when saving it is passed as `encounter` and becomes the scene; the example prepared at saving is shown only when it fits that scene. Teaching stays narrow to that use unless the tutor judges a second example, another use or background worth adding. If teaching fails, no lesson is shown and the word stays new. Finishing the lesson records a `lesson` event with the sentences taught and a graduation policy, A, B or C, drawn at random and stored with its version (`lifecycle.ts`). The assignment is part of the event, not a judgment, so rerunning judgments never redraws it. After two other cards the word comes back as typed recall. If its time runs out first, the session finishes that recall before it ends; if the learner leaves, the word is first in line next session. From then on its lifecycle is derived from the record under its policy: A wants clean recalls one day after teaching and then at least a day later, B one day and then three, C one, three and seven; a clean recall is a correct typed recall on or after its due day, a miss of any bounded kind resets the schedule, and a correct choice counts for nothing. After its last clean recall the word graduates, and fourteen days later one typed recall checks it; a miss reopens it. A word waiting for its first recall ranks first; a due recall or check-up ranks above a fresh need, and scheduled recalls take at most about half of a session's cards. A word taught before lesson cards existed settles like a weakness until two clean days. Daily mix asks for exercises on the top targets first, each target once per session apart from a lesson and its recall, then falls back to recent journal material. Each card records the expression it was asked to practice and its purpose, and the purpose decides which forms the card may take (`formsFor` in `session.ts`); the generator is told the allowed forms and a card in any other form is rejected. Every target, whether a word settling after its lesson, a need or flaw in the learner's own Chinese, a miss, or a word due in the hosted app, is tested by typed recall: a short English cue or phrase cloze, answered by typing the expression as on the hosted app's flashcards and graded by rule against its accepted forms, ignoring spacing and punctuation. A choice is allowed only for a contrast the learner has demonstrably confused: a target missed twice, or a slip in their own Chinese followed by a recall of it. It is never used for a word settling after its lesson. Material without a target becomes either a recall of an expression the learner reached for in it or an open lead-in: a line someone says, drawn from what the material is about, with no required word, frame or content. Feedback on an open answer judges whether the reply landed as an apt response (`landed`, kept with the attempt and its record event but not shown as a grade) and does not point out an expression the reply did without.

`session.ts` holds the session rules. A choice card is estimated at 20 seconds, a typed recall at 25, an open one at 90, and a lesson at 60. Each finished card counts its real time from appearing to Continue, capped at three estimates, and the learner's pace against the estimates scales the cards still ahead. A background worker keeps two cards ready beyond the current one while the prepared cards still fit the budget, committing each one after re-reading the journal so an answer given meanwhile stands. Two failed generations in a row, or nothing left to ask about, stop preparation and show the end state instead of an endless wait. Past the box, only the closing recall is prepared, and the learner sees nothing else until it arrives; if it cannot be prepared, the session ends. `npm run journal:priority` prints the ranking with reasons.

### Intake and admission

A word brought in from Home is first explained, then judged for admission ([learning model](MODEL.md#principles), principle 11). The capture decision marks a word as a **save** when the learner's own words explicitly ask to keep, learn or practice it (save 值得), and as an **ask** otherwise: a bare word, or a word with where they met it. Word intake (`situations/word-intake.ts`) returns, beside the word's gloss and example, an `explanation` of what it means where the learner met it and its register; the reply leads with it and adds one line on practice only if the word is admitted. Every word becomes a saved item, a piece on the board, either way.

Admission is a judgment on the `addWord` event, kept with the others in the record (`admission.ts`). An explicit save is admitted by rule (`rule:admit-v1`): a Home save, a reply to a word clarification that asks to save it (`saveRequested`), the tutor keeping a word on request, and the `addWord` action. An ask goes to a back-office situation (`situations/admit.ts`, never shown), which weighs how useful the word is for this learner to produce against whether understanding it is enough, and records a decision and a reason per word along with the request it read. The offline demo's policy is deliberately simple: it admits its curated words except 图书馆. Admission can be rerun: each event's newest completed judgment counts, a word is admitted when any event's current judgment admits it, and nothing takes back an explicit save. A word that is not admitted stays a quiet piece: priority does not offer it for teaching, and practice material leaves it out.

Every saved word still has a row in `targets`, as its identity and gloss; whether it is taught is derived when priority is ranked. Words saved before admission existed keep their state without a migration: the first open with this version records `admit_from`, and a saved target created before it counts as an explicit save. A word asked about that is also a need or flaw in the learner's own Chinese still ranks as a weakness. Questions that the capture decision sends to the tutor, such as “what does 值得 mean in this sentence”, create no piece and no admission. Reader **Save** keeps a passage, which is not a target.

Not built yet: pieces gaining weight when the same thing is asked about again, and any interface for pieces that were not admitted.

### Learning days

Day-based learning rules use the learner's local day, not the UTC day: recall due days, schedule intervals and the check-up (`lifecycle.ts`), clean days, practiced today and the five-a-day new-word limit (`priority.ts`), and the daily limit on model reads of the learner's language (`judgedToday` in `record.ts`). This deliberately departs, for these rules only, from the repository's UTC date-key policy. Times stay UTC ISO strings in storage; `day.ts` derives each day key from a stored instant and the learner's IANA time zone, so a change of zone or a DST shift moves day boundaries without rewriting history. The zone is a learner setting (`settings.timeZone`): the browser reports its zone on each visit and a different one replaces it. Until a browser has reported one, the server machine's zone stands in, which is right while the journal runs on the learner's own machine. `npm run journal:priority` prints the zone in use. Operational dates stay UTC: backup and log names, the media job's daily model-turn limit, and the times shown in reports.

### Reading the graduation experiment

`npm run journal:priority` (with `--copy` or `--live` for those journals) ends with the experiment. Each word taught on a lesson card has one line with its taught day (the learner's) and assigned policy, then where every policy would place it on the same evidence: `first recall`, `1/2 clean, due 2026-11-26`, `graduated, check-up 2026-12-10`, or `checked pass` / `checked miss`. The assigned policy carries a `*`. Two summaries follow. **Assigned** scores each policy over its own words; this is the experiment's result. **Shadow** replays every word under each policy; it is counterfactual, because the recalls actually asked for followed the assigned schedule, so a shorter policy in shadow sees only the recalls a longer one happened to ask for. Each summary gives words, how many graduated, check-ups passed of those taken, and the mean typed recalls from teaching to the first graduation, including the recall in the lesson's session. Compare policies by check-up pass rate against recalls spent; with a handful of words, read the rows rather than the rates. `--json` prints the same data.
